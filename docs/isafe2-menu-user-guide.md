# iSAFE 2.0 選單使用說明

本說明適用於本地端 iSAFE 2.0 治理介面。實際可見選單與可執行動作依會員等級、案件角色及治理權限決定。

## 案件模式與階段範圍

- 純設計：只建立並顯示 D1-D5；D5 完成雙方勾稽與必要付款後結案，不進入工程階段。
- 直接工程：只建立並顯示 C1-C5；立案受理後由 C1 開始，不建立設計階段。
- 設計＋工程：依序建立並顯示 D1-D5 與 C1-C5。
- 「執行前確認」、逐項檢核、付款里程碑、追加減與 Gate 導覽皆使用同一案件範圍，不適用階段不得顯示或執行。

## 我的工作台

案件導向的每日入口，集中顯示待辦、即將到期工作、缺件及目前治理階段。工作台是操作入口，不取代 Gate 審核。

## 關卡狀態機

查看 D1-D5、C1-C5 的階段狀態、必要證據與可否推進。進入「逐項檢核」時，系統依案件目前 Gate 直接顯示該階段勾稽事項；條文只能在「執行前確認」新增、修改或刪除，設計師／廠商與業主雙方確認後即凍結。每一階段必須完成不可變執行基準、全部必填事項的雙方逐項勾稽、必要證據，以及該階段付款證明與雙方付款確認，Gate 才能進入下一階段。推進後上一階段永久唯讀，不得返回修改、撤銷或覆寫；更正只能建立具版本與稽核軌跡的新變更單或證據修訂。

## 我的案件

選擇及管理案件，查看案件基本資料、執行模式、合約範圍、參與者與進度。案件可採純設計、直接工程或設計加工程模式。

## R8／R5.2 契約

查看契約基線、付款里程碑及版本。工程付款名稱以合約記載的階段工程名稱為準，於該階段完工驗收後支付。

## 案件治理護照

彙整案件治理版本、Gate、證據、決策及跨系統交接紀錄，供追溯與查核。

## 治理 Registry

跨文件與系統統一治理物件。第一項「治理名稱說明」列出九類 Registry 的名稱、代碼及用途，其他分頁呈現各治理登錄資料。

## R9 治理物件

查看 Risk、Trigger、Audit、External Evaluation 等 R9 治理物件及其關聯。物件狀態只能由授權治理流程變更。

## 照片與現場紀錄

認證工程會員上傳施工照片與現場紀錄；業主不代替施工方上傳施工證據。原始檔、修訂版及來源資訊應保留以供追溯。

## 可信知識

以本地 Knowledge／RAG 查詢治理與工程文件，回答應附文件來源與版本標籤。查詢結果是建議，不直接改變 Gate、付款或 R5.2 狀態。

## AI 風險評分

依案件資料與證據產生風險提示及候選評分，供人工判斷。AI 不具核准、付款或結案權限。

## 治理評級

依治理完整度、證據品質、時效及例外處理形成評級，供管理與改善，不取代契約驗收。

## 公會治理中心

供具權限的公會或總部角色查看跨案件治理概況、會員資格及異常事項；可見範圍受租戶與角色權限隔離。

## 操作責任與規則

- 施工照片與現場紀錄：由認證工程會員上傳。
- 付款證明：由業主於對應工程階段完工驗收後上傳。
- 付款名稱：採合約記載的階段工程名稱加「完工驗收款」。
- 追加減工程：可能發生於 C1-C5 任一工程階段，登錄時必須指定發生階段、原因、金額及工期影響。
- AI／RAG：僅提供建議與來源，不直接改變 Gate、付款、契約或 R5.2 狀態。
